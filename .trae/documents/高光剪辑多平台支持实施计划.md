# 高光剪辑多平台支持 — 实施计划

## Context（为什么做这件事）

Clipop AI 的核心功能是「高光剪辑」：用户粘贴视频链接 → AI 找高光 → 输出可下载的竖屏短视频。
但现状是**只有 YouTube 和 Bilibili 真正实现了**：

- `src/app/api/process-video/route.ts` 与 `src/lib/server/video-clipper.ts` 中，除 YouTube（走 CF Worker 流式路径）和 Bilibili（yt-dlp + Referer 头）外，**任何其它平台链接都会落到兜底分支**：`analyzeVideo` 直接返回 `{ duration: 180, highlights: buildFallbackHighlights(180) }`，即**伪造的占位高光**，用户拿不到真实结果。
- 目标：支持 YouTube / B站 / 抖音 / TikTok / 小红书 / Instagram / Vimeo / X(Twitter) 等链接输入，产出真实高光短视频并可下载。

**用户已确认的边界**：
1. **仅做无需登录的公开内容**；平台需登录 / 被风控 / 地区限制时，**给出清晰报错并提示换链接，绝不伪造高光结果**。
2. 上线方式：本地测试通过后，由我 **commit + push 到 main**，触发 Vercel 生产部署。

### ⚠️ 前置阻断问题（必须先修）

## 一、新增平台注册表 `src/lib/server/platforms.ts`

纯数据 + 纯函数、无 IO，便于 tsx 单测：

```ts
export type PlatformId =
  | 'youtube' | 'bilibili' | 'tiktok' | 'douyin'
  | 'xiaohongshu' | 'instagram' | 'vimeo' | 'twitter' | 'generic';

export interface Platform {
  id: PlatformId;
  name: string;           // 展示名，用于报错文案
  hosts: RegExp[];        // 匹配 hostname
  headers: string[];      // yt-dlp --add-header 值，如 'Referer: https://www.bilibili.com/'
  subLangs: string;       // --sub-langs 值
  format: string;         // 下载 -f 选择器
  needsLogin: boolean;    // true → 公开内容也大概率失败，快速给出明确报错
}

export const BILIBILI_HEADERS: string[];              // 从 HEAD L688-693 抽出复用
export function detectPlatform(url: string): Platform; // 命中 hosts，否则 generic
export function mapYtDlpError(stderr: string, p: Platform): Error; // 友好错误映射
```

**平台配置要点**
| 平台 | hosts | headers | format | needsLogin |
|---|---|---|---|---|
| youtube | youtube.com / youtu.be | UA（现有路径，保持） | 现有策略 | false |
| bilibili | bilibili.com / b23.tv / b23.wtf | Referer/Origin/Accept-Language | 现有 | false |
| tiktok | tiktok.com / vm.tiktok.com | UA + Referer: https://www.tiktok.com/ | `best[ext=mp4]/best` | false |
| douyin | douyin.com / v.douyin.com / iesdouyin.com | UA + Referer: https://www.douyin.com/ | `best[ext=mp4]/best` | true |
| xiaohongshu | xiaohongshu.com / xhslink.com | UA + Referer: https://www.xiaohongshu.com/ | `best[ext=mp4]/best` | true |
| instagram | instagram.com / instagr.am | UA | `best[ext=mp4]/best` | true |
| vimeo | vimeo.com | UA | `bestvideo*+bestaudio/best` | false |
| twitter | twitter.com / x.com | UA | `best[ext=mp4]/best` | true |
| generic | — | UA | `bestvideo*+bestaudio/best` | false |

**`mapYtDlpError` 映射**（英文 stderr → 中文/英文友好文案）
- `Sign in to confirm | LOGIN_REQUIRED | not a bot | login required` → “该平台需登录，公开下载不可用，请换一个链接”
- `Unable to extract | Unsupported URL` → “无法解析该链接（平台不支持或链接无效）”
- `403 | Forbidden` → “平台拒绝访问（403），请稍后重试或换链接”
- `GeoRestrict | not available in your country` → “该视频存在地区限制”
- 默认 → “无法下载该视频（平台：{name}），请换链接重试”

## 七、风险与已知坑

- **Vercel 冷启动**：`ensureYtDlp()`（L627）首次从 GitHub 下载 linux yt-dlp 二进制到 `/tmp`，约 10-30s；分析、下载各触发一次。
- **反爬现实**：抖音/小红书/IG 多数内容需登录或签名，`needsLogin` 平台失败率高 → 设计上**快速失败 + 明确文案**，避免白等满 300s。
- **超时**：`maxDuration=300` + `/tmp` 体积上限，长视频必超时 → 必须有明确错误文案，不能静默。
- **`runYtDlp` 联合参数**：必须兼容旧的 `boolean` 调用点，否则引发大面积类型错误。
- **HEAD 恢复是破坏性操作**：执行前先 `git status` 确认，避免误伤其它未提交改动。
- **Bilibili Vercel 路径**依赖 direct API + cobalt 兜底；新增平台不引入新的外部依赖服务。
