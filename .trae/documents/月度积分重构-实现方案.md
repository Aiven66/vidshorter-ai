# 月度积分重构 — 实现方案

> 目标：把付费档从「每日额度」改为「月度额度池」，免费档保持每日 60 不变；消除 Pro 档的伪无限（`1_000_000/天`）与全站 "Unlimited" 文案。
> 前置已上线：P0-3 前半「批量生产队列」已 SHIPPED（生产 E2E 24/24），本方案**不改动**它。

---

## 1. 定价参数（用户已确认，不再变更）

| 档位 | 价格 | 额度 | 周期 | 等价条数（`CREDIT_COST=60`） |
|---|---|---|---|---|
| Free | $0 | 60 | 每日 | 1 条/日 |
| Starter | $9.9/月 | **6,000** | 每月 | 100 条/月 |
| Pro | $19.9/月 | **20,000** | 每月 | 333 条/月 |

- 刷新语义：**UTC 月初 00:00 重置，不结转**（复用现有 `credits.last_reset_at` 字段）。
- 一次性积分包（`credits_120/300/900`）不受影响：加法发放，不重置。

### 必须明示的副作用（已决策，本轮不再发问）

1. **Starter 理论月上限下降**：旧 `500/日` 若天天用满为 `500×30 = 15,000/月`；新为 `6,000/月`。换来的收益是**解锁单日突发**——旧模型下单日最多 500（够 8 条，**连一批 10 条所需的 600 都跑不满**，这正是本次重构的动机）；新模型可在一天内跑满 100 条。
2. **Pro 从伪无限变为真实上限**：旧 `1_000_000/天` 是事实上的无限；新为 `20,000/月`。因此**定价页、公告横幅、首页文案里的 "Unlimited credits" 必须一并改为真实数字**，否则构成虚假承诺。

## 3. 实现方案

### A. 新增单一真源模块 `src/lib/plan-credits.ts`

纯函数、无副作用、server 与 client 共用（不 import 任何 supabase / next 模块）：

```ts
export const FREE_DAILY_CREDITS = 60;
export const PLAN_MONTHLY_CREDITS = { starter: 6000, pro: 20000 } as const;

/** 付费档在 cutoff 之后统一走月度；此前购买且未记录周期边界的旧行走 legacy 日额度 */
export const LEGACY_DAILY_SUNSET_ISO = '2026-10-26T00:00:00.000Z';

export type QuotaPeriod = 'day' | 'month';
export interface Quota { amount: number; period: QuotaPeriod; legacy?: boolean }

export function planQuota(
  plan: string | null | undefined,
  opts?: { legacyPaid?: boolean },
): Quota
// free/未知 → { amount: 60, period: 'day' }
// starter    → { amount: 6000,  period: 'month' }  （legacyPaid 时 → { amount: 500,   period: 'day', legacy: true }）
// pro        → { amount: 20000, period: 'month' }  （legacyPaid 时 → { amount: 1e6,   period: 'day', legacy: true }）

/** UTC 日界 / 月界（返回该周期的起点 ISO 串） */
export function resetBoundary(period: QuotaPeriod, now: Date): string

/** 是否已跨过刷新边界（day 比 y-m-d；month 比 y-m） */
export function hasQuotaCrossed(period: QuotaPeriod, lastResetAt: string | null | undefined, now: Date): boolean

/** 存量旧付费行：有付费 plan 但从未记录周期边界，且未到 sunset */
export function isLegacyPaidRow(plan: string | null | undefined, currentPeriodEnd: string | null | undefined, now: Date): boolean
```

### D. 存量付费用户过渡（决策 3）

- **新购买**：写 `current_period_start/end` → 立即进入月度模型。
- **历史付费行**（`current_period_end IS NULL`，即 cutover 前购买、未记录周期边界）：在 `LEGACY_DAILY_SUNSET_ISO` 之前**继续按旧日额度**（Starter 500/日、Pro 1e6/日），到点自动转月度。用户的「当前计费周期」以 `subscriptions.created_at + 30 天` 作为可解释的近似（无任何续期记录可依）。
- **UI 明示**：legacy 用户在 dashboard 看到「当前周期沿用旧日额度，将于 <日期> 切换为月度额度」，不做静默变更。
- **量级说明**：§2.3 已证实生产仅 admin 一条付费行且已豁免 → 该分支当前为空操作。
