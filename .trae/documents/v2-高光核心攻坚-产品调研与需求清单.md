# Clipop AI v2 产品调研与下版本需求清单

**主题**：高光剪辑核心攻坚（多平台稳定解析 / 精准高光识别与 10 分制评分 / 稳定下载）+ 新用户留存与付费率提升
**调研日期**：2026-10-11
**产品地址**：www.clipopai.com
**技术约束**：尽量不依赖第三方基座模型 API；本地桌面客户端（低电脑配置可跑）+ 在线 Web 端双形态协同

---

## 一、执行摘要

1. **核心功能当前的三个断点**：① 目标的 5 个平台中，抖音 / 小红书 / Instagram 在现有云端链路里被标记为 `needsLogin` 直接失败（见 `src/lib/server/platforms.ts`），只有 YouTube、B 站、TikTok 可用；② 高光打分本质是"云端 LLM 选段 + 批内相对排名映射"（`spreadScores`），不是跨视频可比的绝对质量分，也没有音频、画面、观众反馈等信号参与，无法保证选出来的是"真正的高光"；③ 下载链路历史上多次出现伪 MP4、403、OOM、竖屏失败等问题，目前强依赖 YouTube muxed 合并流（最高 720p）。
2. **开源生态在 2026 年已经可以支撑"不付费给基座模型也做到 OpusClip 级质量"**。MIT/Apache 许可的组件已覆盖全链路：本地 ASR（SenseVoice q8 仅 254MB，CPU 上约 27 倍实时速度）[cite:21][cite:22]、镜头边界检测 TransNetV2（MIT，模型约百MB级）[cite:27]、说话人分离 pyannote（MIT）/ 3D-Speaker（Apache-2.0）[cite:28][cite:29]、本地文本/多模态小模型经 llama.cpp/Ollama 在 8GB 内存机器可跑 [cite:24][cite:31]。最值得对标的产品 HotClip 已验证"九路证据链 + 四维评分 + 复评盲审 + LLM 只引用原文不猜时间戳"的完整架构，但其许可证为 AGPL-3.0，**只能做架构对标，严禁抄代码** [cite:1]。
3. **付费率低的首要原因不是定价，而是免费额度结构**。行业标杆 OpusClip 的免费档是**一次性** 60 积分（1 积分 = 1 分钟源视频）且成片带水印，免费用户验证价值后即面临明确墙 [cite:2]；Clipop 当前是**每天重置 60 积分（约等于 1 次生成）**，轻度用户永远不需要付费，付费动机被结构性消除。Freemium 行业免费转付费中位数约 3–5.5%，优秀水平 8–12% [cite:34][cite:35]。
4. **留存的最大杠杆是"首次成功率"和"价值感知速度"**。消费级 App 的 D1 留存均值 25–28%、优秀 35–40% [cite:37]；新用户触达核心功能的中位耗时应低于 60 秒，超过 2 分钟说明引导在反向伤害留存 [cite:38]。对 Clipop 而言，"第一条高光短视频成功生成并可预览"就是 aha moment，任何一次解析失败/超时/下载到坏文件都直接流失新用户。
5. **v2 建议只做一件主线**：把"任意主流平台链接 → 稳定得到真正高光的竖屏短视频 → 稳定下载"做到接近 100% 可交付，再用"一次性免费额度 + 价值后付费墙 + 低价积分包"完成变现闭环。其余功能（发布、翻译配音、数字人、批量）全部排在主线验证通过之后。

**关键结论**：

- 行业统一价格带是 **$15/$29（约 ¥108/¥208）**，计量口径统一为"源视频分钟数"而不是"成片条数"，这与底层转写/渲染成本结构一致。
- 免费档的设计目标是**让用户体验一次完整价值，而不是长期供养免费用户**：一次性额度 + 水印 + 项目过期是标准组合 [cite:2]。
- 国内市场另有低价心理锚点（HotClip 这类开源免费工具会教育用户"不想被积分制收割"）[cite:1]，因此 Clipop 的付费理由必须落在"云端省事、不占本机、移动端可用、批量与发布"等开源工具给不了的价值上，而不只是"去掉水印"。

### 2.3 最值得对标产品的核心设计：HotClip 九路证据链

HotClip 对"为什么选这段"的公开设计，是目前开源产品中最完整的高光质量方案，可直接作为 Clipop 评分引擎的产品规格参照 [cite:1]：

- **LLM 只负责"挑哪段"并引用原文，时间戳由逐字稿反向对齐**——从机制上杜绝 LLM 幻觉出不存在的时间码；切点精确到词。
- **每个候选输出**：爆款分（0–100，推荐档 76–99）、四维分项（钩子/结构/价值/热点，每维一句话理由）、开场钩子文案、推荐理由；弱片自动标"不建议发布"。
- **分数是排名不是玄学**：四维加权后按同批候选相对排名归一化，避免跨批次分数漂移。
- **多路信号共振**：响度峰值、镜头切换密度、运动峰值（只有音量高可能是 BGM，音量+弹幕+笑声同时出现才是真爆点）。
- **观众信号**：B 站录播姬 `.xml` / 抖音直播 `.jsonl` 弹幕滑窗密度 + 高能词加权；礼物/SC/点赞按互动计权；单人刷屏封顶防伪。
- **情绪信号**：YuNet 人脸 + FER+ 表情模型（几 MB，MIT）找大笑/惊讶/激动峰值；SenseVoice 自带情绪与音频事件标签。
- **镜头切点吸附**：TransNetV2 检测真实镜头边界，切点吸附但词边界守卫绝不切掉说话声。
- **两级漏斗省钱**：本机小模型先初筛，云端模型只精读入围段；模型超时自动降级，绝不阻塞纯文字路径。
- **反馈闭环**：用户采用/否决的候选沉淀为本地偏好；发布后的真实播放/互动 CSV 回流，反哺下一轮选段。
- **商品讲解模式**：按"实测 > 卖点 > 价格机制"选段，排除纯憋单拉互动段——与 Clipop 带货场景高度契合。

## 三、多平台解析与下载方案调研

### 3.1 各方案能力矩阵

| 方案 | 许可证 | YouTube | B站 | TikTok | Instagram | 小红书 | 抖音 | 形态与备注 |
|---|---|---|---|---|---|---|---|---|
| yt-dlp（2026.08 最新版，1700+ 站点） | Unlicense（类公有领域，商用友好） | ✅ 强 | ✅ | ✅（常需更新/风控应对） | ✅ 提取器存在但稳定性随平台变化 | ✅ 已有独立提取器 | ⚠️ 需登录 Cookie，易失败 | 命令行主链路；支持浏览器 Cookie 导入、降频防风控 [cite:16][cite:17][cite:18] |
| cobalt（44.8k stars） | **AGPL-3.0** | ✅ | ✅ | ✅ 视频/图集/音频 | ✅ 帖子/Reels/故事 | ❌ | ❌ | Docker 一键自托管的 HTTP API，适合做内部冗余通道；不面向用户分发即可规避 AGPL 传染 [cite:12][cite:13][cite:14] |
| F2（Johnserf-Seed，2.7k） | Apache-2.0 | — | — | ✅ | — | — | ✅（强项），另含微博/Twitter | Python 库/CLI，抖音解析质量与更新活跃度最好 [cite:15] |
| BBDown（13.9k） | MIT | — | ✅ 多线程/番剧/字幕最全 | — | — | — | — | B站高难度内容（大会员/多P/杜比）兜底 [cite:19] |
| MediaCrawler（66.6k） | 自定义协议（NOASSERTION，**禁止商用**） | — | ✅ | ✅ | — | ✅ | ✅ | 本质是带账号 Cookie 的爬虫，仅可作技术调研，**不可集成进商业产品** [cite:20] |

### 3.2 关键事实

- **抖音是最难的一环**：必须带登录 Cookie，否则大概率失败 [cite:18]；F2 是当前宽松许可下最可靠的抖音解析实现 [cite:15]。
- **小红书**：yt-dlp 已提供原生提取器（2026 版本线），私密/付费内容仍需 Cookie [cite:16][cite:17]。
- **云端服务器 IP 是各平台风控的重点对象**（数据中心 IP 段识别成熟），纯云端解析 TikTok/INS/小红书/抖音天然不稳定；**桌面客户端跑在用户家庭网络（住宅 IP）+ 用户浏览器 Cookie，是行业内稳定性最高的组合**，这也是 HotClip 选择全本地下载的原因 [cite:1]。
- 短链（b23.tv、v.douyin.com、xhslink.com、vm.tiktok.com）均需先做 3xx 展开，现有 `isShortLinkHost()` 已覆盖域名。

### 3.3 推荐架构：三级解析路由 + 双执行端

1. **第一级（云端，快）**：yt-dlp（锁定版本、每月跟升级）→ 失败自动转自托管 cobalt 实例（仅内部 API 调用）。
2. **第二级（云端，增益）**：B 站高难度内容转 BBDown；抖音转独立部署的 F2 解析微服务（Apache-2.0，可商用）。
3. **第三级（桌面端兜底，稳）**：云端任何一级失败或标记需登录时，任务通过已有的 desktop-agent bridge 派发给用户本机——住宅 IP + 用户一键导入的浏览器 Cookie 完成解析与下载，回传成片或源文件。
4. **Cookie 策略**：桌面端支持从本机浏览器只读导入 Cookie（不接触密码）[cite:17]；Web 端不收集用户 Cookie，明确提示"该平台请使用桌面客户端"，不伪造成功结果（这是此前跨平台采集项目的核心教训：失败必须可解释，禁止 mock 兜底冒充成功）。

### 4.2 低配适配原则

- **模型分三档自动选择**：快速档（SenseVoice 170–254MB，全部机型）/ 均衡档（+说话人+镜头检测，8GB）/ 高精度档（+本地 VLM，16GB 或有独显）；任何模型下载失败自动降档并在成片回执里说明，绝不阻塞主流程——HotClip 已验证该产品模式 [cite:1]。
- **首包体积约束**：桌面安装包不内置模型，首次使用时按需下载、国内镜像优先、断点续传、按文件指纹校验（项目 `local-models.js` 已有此机制，扩展即可）。
- **云端不裸奔、本地不越界**：Web 端保留现有后台可配的 OpenAI 兼容 LLM 通道作为"云端增强档"，但默认路径必须在无任何第三方 API Key 时仍可产出结果（本地桌面全量 + Web 端用规则引擎降级），符合"尽量不依赖第三方基座模型"的要求。

## 五、留存与付费转化调研

### 5.1 行业基准

| 指标 | 中位数/均值 | 良好 | 优秀 | 来源 |
|---|---|---|---|---|
| Freemium 免费转付费 | 3–5.5% | 5% | 8–12% | [cite:34][cite:35][cite:36] |
| 消费级 App D1 留存 | 25–28% | 35–40% | 45%+ | [cite:37] |
| 新用户触达核心功能耗时 | — | 应 <60 秒；>2 分钟即伤害留存 | — | [cite:38] |
| 不同品类 D1/D7/D30 参考 | 金融 28/18/12%；中度游戏 45/22/10%；社交通讯 55/35% | — | — | [cite:42] |

### 5.2 对 Clipop 的直接启示

1. **硬付费墙会杀死留存，但"无限量免费"会杀死付费**。研究显示在用户体验到价值之前锁死一切是 AI App 最常见的留存杀手 [cite:39]；而每日重置的 60 积分让低频创作者（剪辑工具的主流人群）永远处于"够用"状态。解法不是加墙，而是**调整额度形态**：
   - 新用户注册一次性发放 60 积分（约 1 次完整生成，对标 OpusClip）[cite:2]；
   - 首次生成成功后给 1 张"第二次生成 7 天内有效"券，制造第二次访问（拉 D7）；
   - 每日签到保留但降为小额（10–15 积分），连续 4–6 天才凑得齐一次——制造"差一点，补 ¥9.9 积分包立刻生成"的转化场景，而不是直接送一次；
   - 免费积分引入 90 天过期，是国内 AI 平台的通行做法且符合财务处理惯例 [cite:41]。
2. **积分是成本与价格之间的解耦层，应按"源视频分钟"计价**，这样模型降价时无需改定价表 [cite:40]。建议补低价积分包（¥9.9/¥19.9）作为订阅之外的入门转化品，对应已规划的 Starter Lite 档；订阅保留"每月分钟数 + 云处理 + 高清无水印 + 批量/发布"等开源工具给不了的价值。
3. **付费墙时机后移到"价值感知之后"**：先让用户看到带评分和理由的高光列表、可在线预览成片，下载/去水印/1080p 时再弹墙。项目现有的"一次性免费下载导出机会 + 导出漏斗埋点"方向正确，继续保留 [cite:39]。
4. **激活定义必须可度量**：激活事件 = 注册后 24 小时内"成功生成并预览至少 1 条高光视频"。当前链路任何一环（解析失败、排队、冷启动 37 秒、下载坏文件）都会让激活率塌缩，因此 P0 的稳定性工作本身就是留存工作。

| 维度 | 现状 | 差距 |

| 平台支持 | `platforms.ts` 已注册 8 平台；YouTube/B站/TikTok 云端可跑，抖音/小红书/INS/X 标记 `needsLogin` 直接失败 | 5 个目标平台中 2 个稳定、1 个部分可用、2 个不可用 |
| 高光选择 | Web：云端 OpenAI 兼容 LLM（DeepSeek/百炼，后台可配）读转写文本选段；无第三方 Key 时降级为本地模板 | 无音频/画面/观众信号；无视觉复核；选段质量完全取决于文本与 prompt |

## 七、v2 产品需求清单

优先级定义：**P0 = 本版本主线（不做即失败）；P1 = 主线验证后的增长项；P2 = 后续版本**。每条含目标、验收标准、技术要点与度量指标。

### P0-1 多平台稳定解析与下载（基础设施中的基础设施）

- **目标**：YouTube/B站/TikTok 成功率 ≥95%，小红书/Instagram ≥85%，抖音通过桌面端 ≥80%；任何失败返回人类可理解的原因，绝不返回伪成功。
- **需求**：
  1. 统一"解析路由表"：平台 → 提取器链（yt-dlp → cobalt → F2/BBDown → 桌面 agent），按健康度自动切换、熔断与恢复；yt-dlp 版本固定并每月跟版升级 [cite:16]。
  2. 自托管 cobalt 作为第二通道（Docker 独立服务，仅内部调用，不对外分发以规避 AGPL）[cite:13][cite:14]；F2 以独立微服务方式承接抖音（Apache-2.0）[cite:15]。
  3. 短链展开、签名过期重试（403 自动刷新一次）、降频请求、浏览器 UA/Referer 平台化配置（已有基础，补齐重试策略）。
  4. 桌面端"浏览器 Cookie 一键导入"（只读本机浏览器会话，不接触密码），用于抖音/小红书/INS；Web 端对登录墙平台直接引导下载桌面端 [cite:17][cite:18]。
  5. 下载产物强制校验：ffprobe 全解码、时长容差 ±2%、moov 前置（faststart）、MIME 与扩展名一致；校验失败不入库、自动换通道重试一次。
  6. 平台成功率实时看板（按平台×提取器×地区统计 success/fail/耗时），作为稳定性回归依据。
- **验收**：200 条真实链接回归集（每平台 ≥30 条，含短链/图集/长视频）连续 3 天达标；所有失败路径有明确 errorCode 与用户文案。

### P0-2 高光质量引擎 v2（本版本的核心差异化）

- **目标**：选出的片段在人工盲评中 Precision@6 ≥85%（6 条里至少 5 条被评审认为"值得剪"），评分跨视频稳定可比，每条给出可信的 10 分制分数与理由。
- **需求**：
  1. **评分模型**（四维 rubric，各 0–10，合成总分映射 1–10 整数 + 同批排名归一化校准）：
     - 钩子力（开头 3 秒是否有提问/冲突/反常识/高能画面）；
     - 信息/情绪密度（金句、观点、数据、笑点点位密度，SenseVoice 情绪标签 + 文本语义）；
     - 完播结构（是否完整意群、时长 21–35s 适配、无断句/断词）；
     - 传播力（话题相关、可引用性、画面可看性、可用时的弹幕/互动热度）。
  2. **证据链输入**：转写文本与词级时间戳、响度曲线、语速/停顿、SenseVoice 情绪/音频事件、TransNetV2 镜头密度、运动峰值、YuNet+FER+ 表情峰值、B 站弹幕（若可得）；多信号共振才加分，单信号（如纯音量高）不采信 [cite:1][cite:27]。
  3. **选段协议**：LLM（云端或本地 Qwen 量化模型）只输出"句子 ID + 四维分 + 理由 + 钩子文案"，**禁止输出时间码**；时间戳由逐字稿反查对齐；切点经镜头边界吸附 + 人声尾音守卫（<1MB VAD 二次确认）[cite:1]。
  4. **复评质量门**：独立"严格评审"prompt 对头部候选二次盲评，两次评分分歧 >2 分的条目降权或丢弃；低于 6 分的候选标记"不建议发布"但保留可见（用户可手动选）。
  5. **三级引擎档**：云端 LLM 增强档（默认，已配置时）→ 桌面本地 Qwen 档（4B/2B 按内存自动选）→ 纯信号规则档（无 Key、无桌面时 Web 仍可用）；档位在结果上透明标注。
  6. **无字幕/无话语降级**：音乐/美食/动作类视频走"镜头+运动+响度+表情"均匀覆盖采样，复用现有 `usedFallback` 机制但必须告知用户判定依据。
  7. **离线评估集防退化**：建设 200 条人工标注 golden set（中英各半，覆盖口播/播客/Vlog/带货/知识/娱乐），每次 prompt/权重改动跑 Precision@k、nDCG、分数校准曲线与用户线上采纳率回归。
  8. **理由与分数 UI**：结果卡展示总分（10 分制醒目）、四维分项徽标、一句话理由、引用原句、钩子文案；分数支持 hover 查看构成，建立用户对评分的信任。
- **许可红线**：HotClip 为 AGPL-3.0，仅按其公开 README 的原理自研，代码、prompt、文案全部独立实现 [cite:1]。

### P0-3 稳定成片与交付 SLA

- **目标**：生成任务"开始后必有明确终态"；新用户首条视频 3 分钟内看到可预览结果（10 分钟以内源视频）。
- **需求**：
  1. 流水线状态机补齐：排队/解析/转写/选段/渲染/校验各阶段进度百分比与阶段文案；8 分钟僵尸对账机制已有，扩展到全部阶段。
  2. 冷启动优化：能力探测等接口预热/边缘缓存，消除 37 秒静默 loading，增加骨架屏与预计耗时。
  3. 渲染失败明确报错并一键重试（沿用现有原则：禁止静默回退低分辨率竖屏）；断点续跑复用已完成片段。
  4. YouTube 源 720p 上限在 UI 明确说明并标注原因；B站/本地源按套餐给 720p/1080p/4K 分层（已有）。
  5. 页面内预览 + 用户手势触发下载（已有正确模式），下载文件以 P0-1 校验通过为准入。
- **验收**：首条视频 P90 端到端耗时 ≤3 分钟；任务卡死率 <1%；新用户首日失败率（含放弃）较基线下降 50%。

### P0-4 新用户首次体验（激活率专项）

- **目标**：注册→首次成功预览的中位耗时 ≤90 秒；激活率（24h 内成功生成并预览 ≥1 条）≥40%。
- **需求**：
  1. **零风险首试**：未登录也能用官方精选示例视频走完整预览（不出下载、不耗积分），登录后再处理自己的链接；首页输入框直达，砍掉所有中间弹窗。
  2. 首次进入即播放 15 秒"输入链接→得到 6 条带分数高光→竖屏预览"的产品演示动图（实测效果而非插画）。
  3. 链接解析中即时反馈平台识别结果、视频标题、时长与预计消耗积分；预计时长 >20 分钟给降档建议。
  4. 失败场景全部给"下一步"：需登录平台→下载桌面端；地区限制→换链接；超时→剪短或桌面端处理。
  5. 结果页默认展开最高分片段自动播放，第一屏即 aha moment。
- **度量**：激活漏斗（打开→粘贴链接→解析成功→生成成功→预览→下载/分享）逐级埋点，按平台与来源拆分。

### P0-5 付费结构改造（付费率专项，不新增重功能）

- **目标**：30 天免费转付费率达到 3%（行业中位数下沿）[cite:35]；ARPPU 通过积分包+年付提升。
- **需求**：
  1. 免费额度由"每日重置 60"改为"注册一次性 60 积分 + 签到小额（10–15/天）+ 首次成功后 7 天二刷券"；存量用户给一次性过渡包，避免口碑事件。
  2. 计量口径由"次"改为"源视频分钟"对齐行业 [cite:2][cite:40]；积分 90 天过期并在 UI 明示 [cite:41]。
  3. 新增 ¥9.9 小额积分包与 ¥19.9 Starter Lite（已规划）两个入门 SKU，付费墙内一键直购（现有付费墙内嵌购买模式延续）。
  4. 付费墙只出现在三个时刻：看到评分结果后点击下载/无水印/1080p 时；免费额度耗尽时；签到差几个积分凑齐一次时（补差价引导）。
  5. 年付默认选中并给 40–50% 折扣锚点；付费墙展示"开源/免费工具 vs Clipop"对比（省本机配置、不占内存、移动可用、自动成片、可批量），不与免费用户拼价格。
  6. 支付失败、价格疑虑提供降级保留：免费用户仍可每日签到慢速累积，绝不硬封 [cite:39]。
- **度量**：曝光→点击→支付成功漏斗、首购 SKU 分布、积分过期前后 7 天转化、退订率。

### P1-1 桌面端"平台下载专家"定位

- 承接 P0-1 第三级：桌面端任务中心新增"云端处理失败→本机继续"按钮；抖音/小红书/INS 链接在 Web 端生成任务后可一键推送到桌面端。
- 浏览器 Cookie 导入、住宅 IP 下载、本机直接出片回传；macOS/Windows 能力对齐（当前 Windows 端缺本地 ASR 与评分模块）。
- 安装包瘦身：模型按需下载，首包保持轻量。

### P1-2 桌面本地高光引擎（HotClip 原理自研版）

- 将 P0-2 的证据链在桌面端落地：TransNetV2 镜头检测、FER+ 表情、弹幕解析（录播姬/直播录制文件）、本地 Qwen 2B/4B 选段、Qwen3-VL-2B 九宫格视觉复核（16GB 机型可选）[cite:24]。
- 本地两级漏斗：小模型全片初筛 → 本地/云端精读入围段 [cite:1]。
- 商品讲解模式（实测 > 卖点 > 价格机制，排除憋单段），契合带货用户。

### P1-3 评分反馈闭环

- 结果卡"采用/弃用/不准"反馈写入偏好（Web 入库、桌面本地存）；用户手动改选的片段作为负样本。
- 已发布视频的播放/互动数据（用户粘贴或导入 CSV/JSON）回流评分模型；一条多版自动 A/B 归因 [cite:1]。
- 模型权重/prompt 迭代以线上采纳率为准绳，配合 P0-2 离线评估集。

### P1-4 结果页增长组件

- 分享页带品牌水印引流（未付费成片）+ 公开分享链接（SEO 落地页，复用现有 SSR 能力）。
- 一键封面帧选择、发布文案与标题生成、逐词卡拉OK 字幕模板（部分已有，做精）。
- "再切 6 条不同风格"二次生成入口，把一次成功变成连续消费。

### P1-5 流失挽回与召回

## 十、风险与合规

1. **AGPL 红线**：cobalt（AGPL-3.0）只作内部独立服务 API 调用、不随产品分发；HotClip（AGPL-3.0）只对标公开设计、禁止复制代码/文案/prompt；MediaCrawler 自定义协议禁止商用，不引入其代码 [cite:1][cite:13][cite:20]。
2. **平台服务条款与风控**：仅处理用户提交的公开视频链接；不批量抓取、不存储源视频、不绕过付费墙；Cookie 仅在用户桌面端本地使用，服务端不留存；抖音等平台明确提示使用桌面端。
3. **版权**：保留与强化现有版权声明与举报渠道；生成内容加水印与来源回链（TikTok 二创已有署名卡机制，推广到全平台）。
4. **低配兼容**：8GB 内存/机械硬盘/无独显为最低支持线；所有重模型可选、可降级；下载与渲染临时文件配额可控，避免重蹈服务端 OOM 覆辙。
5. **付费结构变更口碑风险**：存量每日领取用户给过渡补偿包，公告提前 14 天，签到路径保留但额度调小，避免被对比为"割韭菜"。
