# Clipop AI 下个迭代功能调研

产出「下个迭代版本功能清单」交付物。目标函数始终是**留存率 + 付费率**，不是功能数量。

## 0. 不可动摇的前提

先读 `references/product-context.md`（产品定位、硬约束、能力现状、许可证红线、历史调研结论）。
以下任何一条被违反，方案直接作废：

- 定位是**本地 AI 视频处理器**，核心能力是**高光时刻切片**；**不调用第三方大模型 API**（LLM/VLM/ASR/TTS 一律本地跑）。
- 目标机器是 Apple Silicon 普通 Mac（16GB 统一内存基线），不能假设独立显卡或大显存。
- 开箱即用（组件打进安装包）但**安装包不能过大**——大模型走按需下载。
- 云端只允许承担认证、支付、配置下发、可选的付费重算力档；本地链路必须能独立跑通。

## 1. 先盘点现状，再谈新增

不要凭记忆写功能清单。先确认「哪些已经本地有了、哪些还在走云端」，否则会重复提议已实现的东西：

1. 读 `apps/macos-agent/package.json` 的 `scripts`（`prepare:*` 暴露了已集成的本地能力）。
2. 在 `apps/macos-agent/` 下 grep `ipcMain.handle(` 得到当前 IPC 能力面。
3. 看 `apps/macos-agent/main.js` 与 `local-*.js` / `yuecut-*.js` / `real-human-*.js` 的模块清单。
4. 读 `.trae/documents/` 与 `docs/` 下已有的调研与需求清单文档，避免重复劳动。
5. 用「已有 / 部分 / 缺失」三态总结，作为功能清单的基线。

## 2. 调研两条线，缺一不可

**A. 竞品线（留存与付费机制优先）** —— 调研同赛道产品实际在用什么机制拉动留存和付费，而不是罗列功能。
已知同类（见 references 补充）：Opus Clip、Descript、Submagic、Vizard、Klap、Gling、Kapwing、Recut、Runway、剪映专业版/CapCut、Premiere。重点记录：
- 免费额度与限制形态（次数/时长/水印/分辨率/导出次数）
- 留存的钩子（模板库、批量生产、发布/排期、素材复用、团队协作、历史资产沉淀）
- 付费转化点（哪些能力被卡在付费墙后、升级提示出现在哪一步）
- 本地/离线定位的产品如何定价（一次性买断 vs 订阅）

**B. 开源框架线（决定能不能真做）** —— 只收录能在目标机器跑起来的方案，每个候选必须给出：
- **代码 License 与模型权重 License 分开核对**（红线见 references）
- 目标机器可跑性（MPS / MLX / CoreML / ONNX / ncnn vs 仅 CUDA）
- 模型体积与安装包影响、推理速度量级
- 不确定的一律标注「待核实」，禁止把没验证的写成结论

## 3. 输出格式

每个功能项必须包含这七列，缺一项视为不合格：
用户价值 → **留存杠杆 / 付费杠杆**（至少命中一个，否则删掉）→ 技术方案（框架 + 双 License）→ 硬件门槛 → 安装包体积影响 → 与现有桌面端/粤剪/web 端的集成点 → 风险。

按 P0 / P1 / P2 分级：P0 是本迭代必须交付且能直接拉动指标；P1 是下一迭代；P2 是规划项。
最后必须附：里程碑顺序 + 「待核实清单」（列出集成前必须实测的项）。
